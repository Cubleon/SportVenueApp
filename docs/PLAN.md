# План SportVenue до выпуска

Единый план работ. Идём по этапам сверху вниз. Пункт отмечается `[x]` только
когда он сделан и проверен (для кода — зелёные проверки GitHub). Новые задачи
дописываются в нужный этап, а не держатся в голове.

**Обновлено:** 31 октября 2026, коммит `f275f58`.

**Кто делает:** **К** — Claude (код, тесты, документы) · **В** — владелец ·
**С** — разработчик сервера · **Ю** — юрист / бухгалтер.

**Ограничение по деньгам:** брать деньги с игроков можно только после
открытия ИП и подключения оплаты (ориентир — январь 2027). До этого —
только тестовые оплаты.

## Этап 1. Клиент: что можно сделать без сервера и без решений

- [ ] **К** Тёмная тема: пройти все экраны, поправить контраст и цвета.
- [ ] **К** Крупный системный шрифт: пройти все экраны, убрать обрезания
      и наезды текста.
- [ ] **К** Подготовить код под пуш-уведомления (без ключей: экран
      разрешения, обработка открытия по уведомлению).
- [ ] **К** Подготовить код под сбор падений и аналитику (AppMetrica),
      включается ключом.
- [ ] **К** Контакт поддержки в профиле (адрес даёт владелец — см. этап 2).
- [ ] **К** Проверка доступности: подписи для чтения с экрана у кнопок
      и иконок.

## Этап 2. Решения владельца (без ответа не делать)

- [ ] **В** Редактирование своей игры. Предложение: менять уровень, формат,
      описание; время и клуб после первых оплат не меняются.
- [ ] **В** Название продукта и иконка («SportVenue» — рабочее).
- [ ] **В** Идентификатор приложения. По умолчанию `ru.sportvenue.app`;
      после первой загрузки в магазин не меняется. **Пока не трогать.**
- [ ] **В** Домен для ссылок «позвать друга» (например `sportvenue.ru`).
      Без него кнопка «Позвать игроков» работает только в веб-версии.
- [ ] **В** Контакт поддержки (почта или Telegram).
- [ ] **В** Платёжный сервис: ЮKassa / CloudPayments / Т-Банк — с
      заморозкой денег на долях и чеками агента (см. этап 5).

## Этап 3. Сервер и связка (вместе с разработчиком сервера)

- [ ] **С** Тестовый сервер с адресом, доступный для проверки.
- [ ] **К** Сборка клиента под тестовый сервер; прогон всего пути на живых
      данных: вход → бронь → доли → оплата → отмена → возврат → заявки.
- [ ] **К** Проверка состояния «сервер не отвечает» на всех экранах.
- [ ] **С** Сервер расположен в России (152-ФЗ, локализация данных).
- [ ] **С** Резервные копии базы и слежение за работой сервера.
- [ ] **С** Эндпоинты из раздела «Добавлено 30 октября» документа API
      (ссылки, заявки, отмена игры, по желанию `PATCH /games/{id}`).
- [ ] **С + К** Уведомления: сервер отправляет (заявка одобрена, игру
      отменили, срок оплаты, возврат), клиент показывает.
- [ ] **К** Обновлять документ API при каждом изменении клиента.

## Этап 4. Клубы и каталог

- [x] **К** Черновик каталога «Клубы» (57 строк: падел + платные площадки
      из выгрузки 2ГИС), файл `SportVenue_клубы_Москва.xlsx` у владельца.
- [ ] **В** Открыть доступ к `overpass-api.de`, `data.mos.ru`,
      `apidata.mos.ru`, `padelrus.ru` в настройках среды (через Safari,
      claude.ai/code → среда → Edit → Network access) и подключить
      коннектор Google Sheets.
- [ ] **К** Перенести каталог в Google Таблицу, найти координаты, сверить
      падел с картой Федерации падела, добрать футбол / теннис / баскетбол
      / волейбол из открытых данных.
- [ ] **Ю** Проверить, можно ли использовать данные 2ГИС в своей базе и на
      своей карте. Если нельзя — брать из OpenStreetMap и data.mos.ru.
- [ ] **В** Договориться с первыми 5–10 клубами: цены, расписание, правила
      отмены.
- [ ] **С** Загрузка каталога клубов на сервер.
